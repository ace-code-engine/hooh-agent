# TUI 瑞士风格规范（v1）

> 一句话：**结构靠空白与细线，层级靠灰阶与字重，颜色只表达状态。**
> 验收的终极标准：把颜色全部拿掉，这一屏仍然完全可读、主次仍然分明。

---

## 一、六条不可协商

1. **左对齐，永不居中。** 终端宽度会变，居中的东西每换一个窗口就漂一次；瑞士风格的秩序来自固定的左基线。
2. **不用边框。** 分区只用**整宽细线**。线用 ASCII `-` 或 DEC 线绘 `\x1b(0q…\x1b(B`，**不用 `─`**（East Asian Width = Ambiguous，GBK 下双宽，整列错位）。
3. **一屏只有一个强调色**，其余全是灰阶。成功/警告/错误三色**只在状态标记处出现**，不做装饰。
4. **层级只有五种手段**：空白、全大写+字距（标签）、加粗、三级灰阶、反显（选中）。没有第六种。
5. **不铺背景色。** 让终端底色透出来（铺底色会和用户主题打架，透明终端下还会有缝）。需要"块"时用左侧 2 格竖条 `▌` 或整宽细线。
6. **动画 ≤5Hz，且只在"有事发生"时跑。** 减少动效开关打开后必须完全静止，并给出一个可读的静止帧。

---

## 二、网格

| 单位 | 值 | 说明 |
| --- | --- | --- |
| 页边距 | 2 cell | 左右各 2；120 列 → 内容宽 116 |
| 列间距 | 4 cell | 两列之间是**纯留白**，不是分隔符 |
| 行内间隔 | 1 cell | 同一行元素之间 |
| 块间距 | 1 空行 | 两个语义块之间 |
| 区间隔 | 1 空行 + 整宽细线 + 1 空行 | 分区（细线只在需要"切断"时出现，不是每块都画） |
| 定宽右对齐列 | 编号 / 时间 / 计数 / 百分比 | 一律右对齐、定宽。**表格式对齐是瑞士风格的核心**，不是细节 |

宽度全部按**显示宽度**算（CJK 双宽、`unicodedata.east_asian_width`），不用 `len()`。

---

## 三、层级工具箱（只有这五种）

| 手段 | 实现 | 用在哪 |
| --- | --- | --- |
| 三级灰阶 | `text` 默认前景 / `text_2` 256:245 / `text_3` 256:240 | 正文 / 次要 / 元信息 |
| 标签体 | 英文全大写 + 字距 1；中文不加字距 | `Nº 08`、`STYLE DICTIONARY`、列标题 |
| 加粗 | `SGR 1`，**只用在默认前景上**（Windows 下 bold 会改前景色） | 标题、当前项 |
| 空白 | 语义之间至少 1 空行 | 唯一的"呼吸"手段（终端行高固定 1 行，不能调 line-height） |
| 反显 | 选中行整行反显（不是加背景色） | 列表选中项 |

**不要用 `dim`（SGR 2）** 做"灰色小字"：它不在 Windows Console 的 SGR 表里；用显式灰阶 `38;5;245`。

---

## 四、颜色契约

- **结构色**：`text` / `text_2` / `text_3` 三级灰 + `accent` 一个强调色。
- **语义色**：`ok` / `warn` / `err`，仅出现在状态标记。
- **禁止**"给每个功能配一个颜色"。

ace 现在的 `ui/ace_theme.py` 有 8 个以上色相，收敛如下：

| 旧 token | 新 token | 理由 |
| --- | --- | --- |
| `text` / `dim` | `text` / `text_2`、`text_3` | 灰阶细分为三级 |
| `accent`、`info` | `accent`、`text_2` | info 的青是装饰，降为灰 |
| `tool_pending`、`perm_ro` | `text_2` | 状态由**字形**表达，颜色只区分好坏 |
| `tool_ok`、`goal_active` | `ok` | 合并 |
| `perm_write`、`goal_paused`、`warn` | `warn` | 合并 |
| `tool_fail`、`perm_full`、`error` | `err` | 合并 |
| `user_bg` | **删** | 改用左侧 2 格竖条 `▌` |
| `border` | `rule` | 只用于整宽细线 |

**四档 profile**：truecolor（`38;2`）/ 256（`38;5`，抄 Rich `Color.downgrade()` 的灰阶+6×6×6）/ 16 / 无色。
无色档必须靠**字形**区分而不是颜色（`□` vs `■`、`·` vs `o`），并保证两个不同状态的字形宽度相同。

---

## 五、禁止清单

边框 · 圆角（终端画不出）· 居中 · 一屏两个强调色 · emoji 当结构 · 铺背景色 · 卡片套卡片 ·
>5Hz 的动画 · 没有退路的 Unicode 字形 · 进度条用半格（整格够用；半格留给真正的图表）·
用 `─ ● ■ ◆ · …` 却不带 conhost 退路 —— 这几个在**老 conhost 上实测是 2 格宽**（`█ │ ─` 才是 1 格）。

---

## 六、落到 ace 的模块

| 规范 | 落点 |
| --- | --- |
| 三级灰阶 + 单强调 + 合并语义色 | `ui/ace_theme.py`（`THEMES` 收敛为 3+1+3） |
| 网格、右对齐定宽列、状态段优先级 | `ui/ace_layout.py`（`fit_status_line` 已有优先级，把宽度单位统一到 cell 网格） |
| 整宽细线（含 ASCII / DEC 线绘两档） | `ui/ace_layout.py` 新增 `rule(width)` 纯函数 |
| 反显选中 | `ui/ace_selector.py` |
| 工具卡去边框 → 细线 + `▌` 竖条 | `ui/ace_cards.py`（`GLYPH_FALLBACK` 已存在，补 conhost 双宽字形） |
| 色卡 / 像素工具 | 新增 `ui/ace_swatches.py` |

**规范是渲染器无关的**：实现落在 `ui/`（纯逻辑、可单测），`tui/app.py`（Textual）只做适配层。
否则又是两份实现——这正是之前那份研究里 ace 最大的结构问题。

---

## 七、验收（能断言的部分都写成断言）

1. **颜色纪律**：扫描一屏的 `Segment` 列表 —— `accent` 出现 ≥1 次，其余非语义色出现 **0** 次。
2. **对齐**：每一行的显示宽度 **== 终端宽度**（一条断言抓住全部 CJK 双宽 / 细线变宽的问题）。
3. **无色可读**：剥掉 ANSI 后的 golden 文本逐字比对（没有颜色也得能读）。
4. **响应**：60 / 80 / 120 列各一张 golden。
5. **减少动效**：开关打开时，帧序列长度 == 1。
6. 人眼只确认两件事：色块看着是不是正方形；细线在你的终端里是否连贯。

---

## 八、第一步（改动最小、收益最大）

1. **`ui/ace_theme.py` 收敛**：3 灰 + 1 强调 + 3 语义，旧 token 全部映射过去 → 一个文件，测试能兜底。
2. **`ui/ace_layout.py` 加 `rule(width)` 与网格常量**：纯函数 + golden，不碰 UI。

这两步做完，"瑞士风格"就不再是形容词，而是仓库里能被断言的东西。
