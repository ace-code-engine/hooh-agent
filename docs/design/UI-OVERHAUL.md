## 二、现状盘点（取证）

### 2.1 两个面同时活着

| 面 | 入口 | 代码 | 测试 |
| --- | --- | --- | --- |
| **Ink 前端**（声明的主外壳） | `ace.cmd`（Node + `frontend/node_modules/tsx` 存在时） | `frontend/src/**` | 24 文件 / 333 例 |
| **Python 引擎界面**（真终端默认） | `python ai_code.py` | `ui/ace_*` + `ai_code.py` | 全量 2567 例 |

两个面**各自有一套**菜单、对话框、配色 token、布局口径。同一件事两种长相 —— 这是"丑"的第一来源。

### 2.2 与既有规范的距离（`docs/TUI-SWISS-SPEC.md` §1）

| 规范条目 | Ink 侧 | Python 侧 |
| --- | --- | --- |
| **不用边框**（只用整宽细线） | ✗ **5 处 `borderStyle="round"`**：`ChoiceDialog` `Markdown`（代码块）`Menu` `PermissionDialog` `TaskTree` | ✗ 首屏卡用 `╭╮╰╯─│` 画框；而 `ai_code.py:441` 自己把这些字符列进"高危字形，别赌" |
| **一屏只有一个强调色** | ✗ 直接吃 ANSI 16 色（`theme/tokens.ts:55-66`）：菜单框黄、选中品红、标题青 | 部分收敛（`ace_theme.CELL_THEMES`），首屏仍是多色 |
| **动画 ≤5Hz，可静止** | ✗ 每个 delta 整屏重绘 | ✓ 有 `ACE_REDUCE_MOTION` |
| 左对齐不居中 | 大体左对齐 | ✓ |

### 2.3 两个结构性问题（配色改不动的）

- **(a) Ink 侧没有 `<Static>`**：整份转录都在动态帧里，于是
  ① 终端**回滚缓冲里没有历史** → 往上翻不了；
  ② 每个增量都**整屏重画** → 频闪；
  ③ 首屏横幅随 `items` 变化消失（`App.tsx:296`）。
  （Python 引擎早就用了两车道：定稿进真实 scrollback，底部区才走帧缓冲。）
- **(b) 两个面各有一份"菜单开合/回车语义"**：目前靠**跨语言对拍**测试钉住（`ARGUMENT_HINTS` 两表一致），
  但**对话框、卡片、配色没有对拍** → 会继续漂。

## 三、目标与三条不变量

**目标**：一份规范、一个主面、两个面同源。

1. **规范就是规范**：左对齐 / 无框 / 单强调色 / 五级层级 / 不铺底色 / ≤5Hz（规范 §1 六条）。
2. **界面不许吃掉回滚缓冲**：任何屏幕都该能一路往上翻；清屏只允许出现在"用户主动"（Ctrl+L）与退出时。
3. **Windows 上也得对**：CJK 按显示宽度算；Ambiguous 宽度字符走白名单（规范 §1 第 2 条已有黑名单）。

## 四、路线（**要你选**）

| 路线 | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |
| **A** | Ink 前端按规范重做（去框、收色、加 `<Static>`、配色对拍） | 大：TS 24 文件 + 组件测试 | 中：Ink 在 Windows 的 Static/滚动有老坑（频闪本身就可能来自它） |
| **B** | **Python 引擎界面为主面**，Ink 冻结（只修 bug，不再加视觉） | 中：只做 `ui/ace_*` | 中：与 WP-0"frontend 是唯一主外壳"的既有决策**相反**，要正式改那个决策 |
| **C** | 两个面都留，只共用一份 token + 规范，视觉逐项对齐 | 小步，但**长期两份工** | 高：这正是过去几个月漂移的老路 |

**我的建议：以 B 为骨架、用 C 的手段兜住 Ink**——
Python 引擎当主面（它有随附规范、双车道回滚、2567 例、零依赖），
Ink 只做两件事：**去掉 5 处边框**、**token 与 Python 对拍**；不再追平视觉。

理由不是偏好：Ink 那侧的"频闪 + 不能往回翻"是**平台层**问题（Ink 的动态帧模型），
而 Python 侧的两车道**已经在测试里验过**（帧预算 2.3ms / 空转 0.13ms）。

## 六、验收标准（能断言的都写成断言）

1. `python -m ui.ace_swatches --check`：现有 **13 组断言**全绿（含三后端宽度一致、golden、帧预算）。
2. **新增规范断言**：渲染输出里**不出现** `╭ ╮ ╰ ╯ │ ┌ ┐ └ ┘ ─`（无框）；一屏**只有一个强调色**（`problems()` 已在管，扩到全部屏幕）。
3. **字形白名单**：输出只允许 ASCII + 白名单；CJK 一律按 `display_width`；golden 覆盖 **60 / 80 / 120** 三宽度。
4. Ink 侧：`tsc --noEmit` + 333 例全绿；**边框数 = 0**；token 与 Python 对拍一致。
5. **你能一眼确认的**：P0 截图清单逐项打勾 —— 这条是唯一不靠测试的验收项，也是过去几次"我改完你没看到"的根因。

## 七、明确不做

- **不动引擎核心逻辑**：权限、快照、审计链、协议一律不碰；这次只动表现层。
- **不引第三方 UI 库**：Ink 侧只用 Ink，Python 侧零依赖（ADR-004 的底线）。
- **不做炫技动画**：规范第 6 条 ≤5Hz、关掉动效必须完全静止并给出可读静止帧。
- **不"两个面各写一套新样式"**：那就是路线 C 的坑，也正是现在丑的来源。
